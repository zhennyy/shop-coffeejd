# Запуск магазина-бота для нового клиента

Шаблон: Telegram-бот + мини-приложение магазина + админка внутри Telegram. Один клиент = один отдельный бот, один сервис на Railway и один постоянный диск. Данные клиентов не смешиваются.

## 1. Что нужно от клиента

- Название магазина, логотип, список товаров с ценами, остатками и фото (можно таблицей Excel: колонки `id; товар; вариант; категория; цена_руб; остаток; описание`).
- Города доставки и цены; нужен ли самовывоз и его адрес; нужны ли СДЭК/Почта и доставка по расстоянию (тогда адрес, откуда отправляют).
- Аккаунт ЮKassa (магазин и секретный ключ) — только если нужна онлайн-оплата.
- Telegram владельца (откуда будут приходить заказы).

## 2. Создание бота (5 минут)

1. В Telegram откройте @BotFather → `/newbot` → имя и username → получите токен. Токен никому не отправляйте.
2. Узнайте `OWNER_CHAT_ID` владельца: владелец пишет боту @userinfobot, тот отвечает числом.

## 3. Развёртывание на Railway

1. Скопируйте папку шаблона в новый приватный репозиторий GitHub под клиента (например `shop-<клиент>`). Не кладите в репозиторий базу данных и файл `.env`.
2. Railway → New Project → Deploy from GitHub repo → выберите репозиторий.
3. Добавьте **Volume** (постоянный диск), путь монтирования `/data`. Без него заказы и остатки пропадут при перезапуске.
4. В **Variables** задайте (значения вводите сами в интерфейсе Railway):

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `OWNER_CHAT_ID` | числовой id владельца |
| `BOT_USERNAME` | username бота без @ |
| `DB_PATH` | `/data/shop.db` |
| `PUBLIC_URL` | адрес сервиса, `https://…up.railway.app` (Settings → Networking → Generate Domain) |
| `SHOP_URL` | `PUBLIC_URL` + `/shop/` — ссылка на мини-приложение |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | данные ЮKassa (если нужна оплата) |
| `YOOKASSA_RECEIPTS` | `on` — формировать чеки 54-ФЗ (см. раздел 5), иначе не задавать |
| `RECEIPT_VAT_CODE` | код НДС для чека (по умолчанию 1 — без НДС), уточните у бухгалтера |
| `RECEIPT_TAX_SYSTEM` | система налогообложения, код 1–6 (если нужна по договору с ЮKassa) |
| `CRM_URL`, `CRM_SECRET`, `CRM_SOURCE` | только если подключаете CRM; `CRM_SECRET` — длинная случайная строка, одинаковая в боте и CRM |

5. В личном кабинете ЮKassa → Интеграция → HTTP-уведомления: адрес `PUBLIC_URL/yookassa-webhook`, событие `payment.succeeded`.
6. В BotFather: `/mybots` → бот → Bot Settings → Menu Button → укажите `SHOP_URL`.

## 4. Наполнение и настройка (владелец делает сам в боте)

1. Откройте магазин из бота → вкладка «Админ» (видна только владельцу).
2. Товары: добавить вручную или отправить боту команду `/stock` — он пришлёт таблицу CSV; правьте в Excel и отправьте файл обратно. Варианты (250 г / 1 кг) — это отдельные строки с одинаковым названием и разным «вариантом».
3. Настройки → Доставка: города и цены, «бесплатно от», самовывоз; блок «СДЭК / Почта» (цены задаёт владелец) и «По расстоянию» (адрес отправки + ступени `5 : 200`, строка = «до N км : цена ₽»).
4. Промокоды, пробный заказ.

## 5. Чеки 54-ФЗ — важно

Я не юрист и не бухгалтер; требования к чекам зависят от статуса клиента. Перед включением `YOOKASSA_RECEIPTS=on` клиент должен подтвердить с ЮKassa и бухгалтером:

- ИП/ООО на ККТ: подключена «Чеки от ЮKassa» или своя онлайн-касса; в настройках платежей включена отправка чеков; верны система налогообложения и ставка НДС.
- Самозанятый: чеки формирует сам клиент в приложении «Мой налог»; чек ЮKassa в этом случае, как правило, не нужен — оставьте `YOOKASSA_RECEIPTS` выключенным.

При включённых чеках покупатель обязан указать телефон или e-mail; сумма позиций чека всегда равна сумме платежа (проверено тестами). Доставка идёт отдельной позицией-услугой.

## 6. Проверка перед сдачей (чек-лист)

- Заказ самовывозом, курьером, СДЭК/Почтой, по расстоянию — в каждом считается верная цена.
- Тестовая оплата ЮKassa: заказ стал «Оплачен», остаток уменьшился, владельцу пришло сообщение, покупателю — подтверждение.
- Отмена оплаты не оставляет «зависших» заказов.
- «Повторить заказ» и «Повторять регулярно» (в разделе «Заказы»).
- Резервная копия: кнопка в админке присылает ZIP в чат владельцу — сделайте первую сразу после наполнения.
- Автотесты шаблона: `npm test` (21 проверка: заказы, доставка, чеки, подписки, безопасность).

## 7. Подписки (регулярные заказы)

Деньги автоматически не списываются. В назначенный день бот собирает заказ по текущим ценам и присылает ссылку на оплату; не оплатили — ничего не списывается. Если товара нет, перенос на день, после 3 переносов подписка ставится на паузу. Покупатель может пропустить, поставить на паузу и отменить в разделе «Заказы».

## 8. Безопасность

- Токены и ключи хранятся только в Variables Railway, не в коде и не в чате.
- Доступ к магазину и админке проверяется подписью Telegram; админ-маршруты — только для `OWNER_CHAT_ID`.
- Оплата подтверждается запросом к ЮKassa, сумма сверяется с заказом.
- Включены ограничения частоты запросов (в том числе защита промокодов от подбора), защита от скачивания фото из внутренней сети, экранирование формул в CSV.
- Репозитории клиента держите приватными, базу в Git не добавляйте.

## 9. Ограничения, о которых стоит предупредить клиента

- Расстояние считается по прямой (через OpenStreetMap), а не по дороге. Если сервис карт не ответил, покупателю предложат другой способ доставки.
- Цена СДЭК/Почты фиксированная, её задаёт владелец; точный тариф перевозчика бот не запрашивает.
- Подписки — напоминание с оплатой, не автосписание.
