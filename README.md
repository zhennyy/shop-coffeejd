# CoFFeeJD — магазин кофе и чая в Telegram

Telegram-бот и мини-приложение магазина: витрина, корзина, оплата через ЮKassa, доставка и админка для владельца внутри Telegram. Шаблон настраивается под разные магазины: меняются каталог, цены и условия доставки.

## Что умеет

- **Каталог.** Варианты товара (до двух параметров), продажа на вес и объём (граммы, миллилитры), доп. товары, наборы со складом из составляющих, сортировка и фильтр «в наличии».
- **Склад.** Остатки, загрузка и выгрузка в Excel и CSV, отчёты за период (`/report`), предупреждения о малом остатке.
- **Доставка.** Самовывоз, курьер по городам, СДЭК и Почта (фиксированные цены), расчёт по расстоянию. Бесплатная доставка от суммы.
- **Оплата.** ЮKassa с проверкой платежа на сервере. Чеки по 54-ФЗ включаются отдельной переменной.
- **Заказы.** Статусы с пояснениями, повтор заказа, регулярные заказы (напоминание с оплатой, без автосписания).
- **Админка.** Внутри мини-приложения, только для владельца: товары, заказы, промокоды, доставка, настройки, отчёты, резервная копия.
- **CRM.** Заказы можно отправлять в отдельную MiniCRM (клиенты, склад, задачи с напоминаниями).
- Два языка: русский и английский.

## Запуск

Нужен Node.js 22.12 или новее (так требует Prisma). Подробная инструкция для клиента: [ЗАПУСК_ДЛЯ_КЛИЕНТА.md](ЗАПУСК_ДЛЯ_КЛИЕНТА.md).

```bash
npm install
npm start
```

Переменные окружения (задаются в `.env`; на сервере — командой `bfa env coffeebot`; значения в репозиторий не кладём):

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `BOT_USERNAME` | username бота без @ |
| `OWNER_CHAT_ID` | числовой id владельца |
| `DB_PATH` | путь к базе, на сервере `/data/coffeebot/shop.db` |
| `PUBLIC_URL`, `SHOP_URL` | адрес сервиса и ссылка на мини-приложение (`PUBLIC_URL` + `/shop/`) |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | данные ЮKassa, если нужна онлайн-оплата |
| `YOOKASSA_RECEIPTS` | `on`, чтобы формировать чеки 54-ФЗ (сначала уточните у бухгалтера) |
| `CRM_URL`, `CRM_SECRET`, `CRM_SOURCE` | только для подключения CRM |

| `TELEGRAM_API_ROOT`, `ANTHROPIC_BASE_URL` | посредники для Telegram и Claude, если сервер в России |

Webhook ЮKassa: `https://botforall.ru/yookassa-webhook` (общий для всех магазинов на сервере; каждый бот проверяет платёж и берёт только свой), события `payment.succeeded` и `payment.canceled`.

Работает 24/7 на своём сервере (VPS): код в `/opt/bots/coffeebot`, база и фото в `/data/coffeebot` — обновления (`bfa update`) их не трогают, каждую ночь делается резервная копия. Магазин: `https://coffee.botforall.ru/shop/`. Установка сервера — в [BotForAll/deploy/README.md](https://github.com/zhennyy/botforall/blob/main/deploy/README.md).

## Проверка

```bash
npm test              # автотесты
npm run lint          # ESLint: ошибки и понятные имена (без однобуквенных переменных)
npm run format:check  # Prettier: единый стиль кода (npm run format — поправить)
npm run test:ui       # мини-приложение в браузере (Playwright)
```

59 автотестов: заказы, остатки, доставка, чеки, подписки, наборы, Excel, CRM, безопасность, персональные данные (согласие, уведомления без контактов, миграция старой базы) и сам бот в чате (через подставной Telegram). Тесты лежат рядом с кодом — файл `test.js` в папке модуля или маршрута; `npm test` находит их сам. Тесты не заменяют проверку с настоящей ЮKassa и Telegram.

На каждый push и pull request GitHub Actions запускает Prettier, ESLint и тесты (`.github/workflows/ci.yml`).

## Структура

`index.js` — точка входа: проверяет `.env`, запускает бота, сервер и фоновые задачи. Всё остальное — в `src/`, каждый механизм в своей папке:

| Папка | Что внутри |
| --- | --- |
| `config/` | чтение и проверка `.env` |
| `database/` | подключение к SQLite через Prisma, миграции, стартовые данные |
| `bot/` | Telegram-бот: команды, кнопки, сценарий оформления (`scenes/`), проверка владелицы (`middleware/`) |
| `server/` | Express: API мини-приложения и админки, вебхук ЮKassa, фото товаров |
| `orders/`, `cart/`, `checkout/`, `pricing/` | заказы, корзина, оформление, цены и промокоды |
| `inventory/` | склад, количества на вес, импорт/экспорт Excel и CSV |
| `delivery/`, `payments/` | доставка и онлайн-оплата с чеками |
| `subscriptions/`, `chat/`, `notifications/`, `crm/` | повторные заказы, переписка с покупателями, уведомления, CRM |
| `reports/`, `backup/`, `schedulers/`, `i18n/` | отчёты, резервная копия, задачи по расписанию, тексты RU/EN |

Подробнее о сервере: `server/index.js` собирает приложение, фото товаров — в `server/photos.js`. Каждый маршрут — своя папка в `server/routes/`:

```
server/routes/checkout/
  index.js       — маршруты
  validation.js  — проверка входящих данных (middleware перед маршрутом)
  test.js        — тесты этого маршрута
```

Маршруты: `shop` (витрина), `checkout` (оформление), `admin-products`, `admin-orders`, `admin-settings` (админка), `yookassa` (вебхук оплаты). Проверка разбирает запрос и кладёт готовые значения в `request.validated` — сам маршрут работает уже с ними. Бот: `bot/index.js` подключает обработчики из `bot/handlers/` (старт, каталог, корзина, AI-консультант, команды владелицы).

### База данных

Работа с базой — через ORM [Prisma](https://www.prisma.io): запросы пишутся на JavaScript, без SQL.

```js
const recentOrders = await database.order.findMany({ where: { chat_id: chatId }, orderBy: { created_at: 'desc' }, take: 20 });
```

- `prisma/schema.prisma` — схема всех таблиц.
- `prisma/migrations/*.sql` — изменения структуры базы; применяются сами при запуске, каждая один раз.
- Клиент Prisma генерируется автоматически после `npm install` (`npm run db:generate` — вручную).
- Несколько изменений, которые должны пройти вместе (оплата, склад), оборачиваются в `runInTransaction(...)`.

### Мини-приложение

Витрина и админка владелицы — `shop-public/`, без сборщика: браузер грузит ES-модули, сервер отдаёт папку как есть (`/shop`).

```
shop-public/
  index.html   — только разметка; подключает styles/*.css и scripts/main.js
  styles/      — base.css (цвета, светлая/тёмная тема, кнопки) + по файлу на раздел
  scripts/
    main.js, navigation.js        — запуск, вкладки, кнопки Telegram (MainButton/BackButton)
    api.js, state.js, i18n.js, telegram.js — запросы к /shop-api, общее состояние, тексты RU/EN, Telegram SDK
    utils/                        — форматирование цен и дат, экранирование, тосты, делегирование кликов (data-action)
    catalog/, cart/, checkout/, orders/, ai/ — разделы покупателя
    admin/                        — products/, orders/, stats/, chats/, settings/
  legal/       — privacy.html, consent.html, offer.html (+ legal.css): политика, согласие, оферта
```

Кнопки в разметке помечены `data-action="…"`; обработчики регистрируются по имени, слушатель кликов один. Проверка в браузере: `npm run test:ui` (Playwright, скриншоты всех экранов покупателя и владелицы; `-- --compare <папка>` сравнивает с прошлым прогоном).

## Персональные данные (152-ФЗ)

Что сделано в коде:

- **Согласие перед оплатой.** В оформлении — отдельная галочка «Я даю согласие на обработку персональных данных» (не отмечена заранее) со ссылками на согласие, оферту и политику. Без неё «Оплатить» показывает подсказку и заказ не создаётся; сервер тоже отвечает 400 без `consent: true`. В чат-оформлении бота — кнопка «✅ Согласен на обработку данных». Время согласия хранится в заказе (`orders.consent_at`, миграция `003_consent_at.sql`).
- **Регулярные заказы.** Подписка копирует `consent_at` из заказа, по которому оформлена, а заказы по подписке — из подписки: покупатель новых данных не вводит, сервер повторяет заказ по уже согласованным. У подписок, оформленных до этого изменения, `consent_at` пустой — согласие задним числом не придумываем.
- **Telegram без персональных данных.** Telegram — зарубежный сервис, поэтому в сообщениях владелице нет телефона, адреса и имени покупателя: только номер заказа, состав, сумма, способ доставки и город, статус и строка «Контакты и адрес — в админке» с кнопкой админки. Ссылка на покупателя в Telegram и кнопка «Написать покупателю» остались. То же в `/orders`, в оценке заказа, в пересылке сообщений (только имя из профиля Telegram) и в резервной копии, которую бот присылает в чат (адресов, телефонов и e-mail в ней нет). Телефон и адрес владелица видит в админке — она на нашем сервере. Покупателю его собственный адрес в уведомлениях показывается, как раньше.
- **Документы.** Шаблоны в `shop-public/legal/`: политика обработки данных, согласие и публичная оферта (открываются по адресу `/shop/legal/…`). Там описано: какие данные, зачем, где хранятся (сервер в России), кому передаются (ЮKassa, служба доставки, CRM; AI-консультант получает только текст запроса и каталог; для доставки «по расстоянию» адрес без имени и телефона уходит в геокодер OpenStreetMap), срок хранения, права и отзыв согласия.

Что сделать владельцу магазина перед запуском:

1. Заполнить реквизиты в трёх файлах `shop-public/legal/*.html` — всё в [КВАДРАТНЫХ СКОБКАХ]: наименование или ФИО ИП, ИНН, ОГРНИП/ОГРН, адрес, e-mail, телефон, дату редакции. Потом убрать жёлтую плашку «Шаблон: заполните реквизиты перед запуском».
2. Подать уведомление в Роскомнадзор об обработке персональных данных (как оператор ПД) — на сайте pd.rkn.gov.ru.
3. Дать юристу проверить тексты (особенно сроки хранения, условия возврата и передачу данных третьим лицам) и поправить под свой магазин.

## Безопасность

Доступ к мини-приложению проверяется подписью Telegram, админ-маршруты доступны только владельцу. Платёж подтверждается запросом к ЮKassa с проверкой суммы. Есть ограничение частоты запросов, защита от подбора промокодов и от загрузки картинок из внутренней сети. Токены и ключи хранятся только в переменных окружения.
